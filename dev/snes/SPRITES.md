# Sprites module (snes/src/spr.s + src/Tools/Snes/SnesSprites.cs)

Owner: sprites agent. Everything below is generated by `smb4tools snes-export OUTDIR` (step `sprites`).

## Files
* `gen/spr_ids.inc` — constants: metasprite ids, `FORM_*`, `POSE_*`, `PPAL_*`, flag bits, `SPR_LEVEL_*`.
* `gen/spr_data.s` + `gen/spr_chr*.bin`, `gen/spr_ppool*.bin` — data in **BANK32-BANK39** (filled from 39 down; currently 35-39).
* `gen/spr_report.txt` — per level: combos, palette groups, VRAM cells/singles used, quantization error; bank map.

## API (JSL/RTL, enter/exit A8 XY16, DB=$80)
| routine | args | notes |
|---|---|---|
| `spr_begin` | – | start of frame: hides all 128 sprites |
| `spr_meta` | `spr_arg_id`, `spr_arg_x/y` (16-bit signed screen coords of the image top-left = C# `ppu.Spr(img,x,y)`), `spr_arg_flags` | draws one metasprite; ids not loaded in this level draw nothing |
| `spr_player` | A = `FORM_*`, X = `POSE_*`, `spr_arg_x/y` = top-left of the 16x32 player box (C# `Px-camX, Py-camY`), flags | queues the frame's CHR (OBJ tiles 0-31) + palette 8 for NMI, adds its OAM entries |
| `spr_end` | – | packs the OAM high table |
| `spr_nmi` | – | (main.s) OAM DMA 544 B, player CHR (≤5 pieces × 128 B, only when the frame changed), palette 8 (32 B, only when changed) |
| `spr_level_load` | A = level index (`LVL_*` of `gen/levels.inc`; `SPR_LEVEL_HB` = 54 follows) | **forced blank**; OBJ tiles 32-511 + CGRAM palettes 9-15; ~0.8-1.0M cycles (~0.3 s); selects the level's start area |
| `spr_area` | A = area index | theme-colored ids (below) follow that area's theme. **Call after `spr_level_load` whenever the current area changes.** |
| `spr_meta_size` | `spr_arg_id` → X = width, Y = height (0,0 = not loaded) | |

**Draw order:** later calls get lower OAM indices = drawn in front (C# painter's order works as is). If the PPU reported
a sprite-line overflow last frame (STAT77), the OAM start slot rotates each frame so dropped sprites flicker.
Pieces are culled outside x −16..255 and y −16..191 (playfield).

### spr_arg_flags
`SPR_HFLIP $0001` (mirror/face left) · `SPR_VFLIP $0002` · `SPR_BEHIND $0004` (OBJ priority 2: hidden by high-priority BG1
tiles; normal sprites use priority 3 — see DESIGN.md note) · spr_meta: bits 4-7 = palette override (`$80`-`$F0` = OBJ pal 8-15).
spr_player only: bits 8-9 tail pose `SPR_TAIL_DOWN/MID/UP` (Raccoon/Tanooki big poses) or `SPR_TAIL_SPIN` (spin poses: tail
sticks out — front spin: facing side, back spin: opposite side, exactly as PlayerDraw) · `SPR_STARPAL $0400` + bits 11-12 = the
C# `BodyPalette` star k (0 mario/luigi, 1 fire, 2 pstar.1, 3 pstar.2) · `SPR_PFLASH $2000` (transform flash) · `SPR_LUIGI $4000`.
Palette priority = C#: `POSE_DEATH` → plain mario/luigi; star; `POSE_STATUE` → statue; pflash; form palette.

## Ids
* Plain ids: `SPR_` + art image name uppercased, `.`→`_`; a non-default palette adds a suffix:
  `SPR_KOOPA_1` (green) / `SPR_KOOPA_1_RED`, `SPR_SHELL_1..4[_RED]`, `SPR_MUSHROOM` / `SPR_MUSHROOM_ONEUP`, `SPR_FLOWER_1` /
  `SPR_FLOWER_1_FLASH` (flower.2), `SPR_STAR` / `SPR_STAR_2..4` (star.2-4 palettes), `SPR_BOBOMB_1_FLASH`, `SPR_PUFF_1..3_HOT/_WARM`
  (Explosion palettes), `SPR_ROTODISC_2`, `SPR_RING_1/2` (ring.a) `SPR_RING_1_B/2_B`, boss `*_FLASH` variants,
  `SPR_KOOPALING_*` (this level's world Koopaling colors), `SPR_KL` (this world's Koopaling accessory), `SPR_CHEST` (hb).
  Full list with image/palette: `gen/spr_ids.inc`.
* Theme-colored ids (resolved by `spr_area`): `SPR_BUMP_BRICK SPR_BUMP_USED SPR_BUMP_NOTE SPR_BUMP_NOTE_2 SPR_BUMP_WOOD
  SPR_DEBRIS SPR_SPLASH_1 SPR_SPLASH_2 SPR_SEMI_L SPR_SEMI_C SPR_SEMI_R SPR_GOAL_BOX` (`SPR_BUMP_USED` = donut lift too).
* Per level only what can appear is loaded: common set (coins, score digits, puffs, sparkle, dust, fireballs, hammers,
  mushroom) + block contents + spawn codes + goal/bosses. Missing combos just don't draw — tell me if one is needed.

## Player
* `POSE_*` = PlayerDraw frame names without `ms.`/`mb.`: `STAND WALK RUN1 RUN2 JUMP PJUMP SKID DEATH FRONT KICK HOLD1 HOLD2
  SWIM1-3 CLIMB1-2 SLIDE WALK1 WALK2 RUN3 FALL DUCK THROW SPINFRONT SPINBACK FROG_STAND FROG_HOP1 FROG_HOP2 FROG_SWIM1-3
  FROG_FRONT STATUE`. Small form uses ms.*, big forms mb.* (+ suit overlays composited by the real `DrawSuited`/`Body`);
  mismatches fall back sensibly (big WALK → WALK1, small DUCK → STAND, DEATH is always the small frame).
* Frames are pre-composited per (form, pose, tail pose), sliced into ≤8 16x16 pieces on the best-fitting 16-px grid
  (bodies up to 24x36 + tail/ears fit), deduplicated (305 pieces / 194 frames).
* Palette 8 per (form, variant) = `spr_ppal_tab`; Raccoon tail colors are mapped to the nearest body slots (mario uses all 15).
* For the grow/shrink flicker pass `FORM_BIG`/`FORM_SMALL` explicitly (C# draws those plain).

## VRAM / CGRAM
OBJ tiles 0-31 = player frame area; 32-511 = level set (16x16 cells from the front, 8x8 singles from the back; max use 91/120
cells). Palettes: 8 player, 9-15 level set (all item/enemy/boss palettes of the level packed + quantized to 7x15 colors).

## Testing
Standalone test ROM (my scratch folder `snes-spr/test`): `levtest.sh` exports with `SMB4_SPR_REF=dir` (writes `ref_<level>.png`,
the exact expected screen), builds `main.s + spr.s + test game.s`, runs Mesen and pixel-compares: 1-1 1-f 1-a 3-3 7-5 5-4 hb 4-a
are pixel-exact (8-c's page exceeds 128 sprites by design). Player pages are compared visually with `smb4tools poses FORM`.
